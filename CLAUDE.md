# mlog.guide

Интерактивный учебник и песочница по логике Mindustry (mlog), на русском. Документация языка плюс
интерпретатор и симуляция мира прямо на странице.

Проект пишется с нуля. Семантика берётся из исходников игры, не из чужих реализаций.

## Контекст между сессиями

Работа рассчитана на много сессий. Перед началом читать:

| Файл | Что в нём |
| --- | --- |
| `PLAN.md` | Опись инструкций, граница v1, модель песочницы, порядок работ |
| `docs/decisions.md` | Журнал решений: что выбрали и почему. Дополнять при каждом новом решении |
| `docs/findings.md` | Семантические детали mlog, найденные в исходниках, со ссылками на Java |

Новое решение — строка в `docs/decisions.md`. Новая деталь поведения из исходников — строка
в `docs/findings.md` **и** тест.

## Источник истины

**Mindustry v159.7**, тег зафиксирован. Обновление версии — отдельная осознанная задача, а не
«подтянуть последнее».

Исходники не лежат в репозитории. Развернуть локально:

```bash
git clone --depth 1 --branch v159.7 --filter=blob:none --sparse https://github.com/Anuken/Mindustry.git
git -C Mindustry sparse-checkout set core/src/mindustry/logic core/src/mindustry/world core/src/mindustry/content core/src/mindustry/type core/assets
```

Главное — `core/src/mindustry/logic/LExecutor.java` и `LStatements.java`.

## Лицензия

GPL-3.0, как у Mindustry. Списывать из Java напрямую можно и нужно — точность важнее оригинальности.

## Стек

- **Ядро** (ВМ + модель мира) — чистый JS, ноль зависимостей, ноль импортов из фреймворка.
  Запускается и тестируется в ноде.
- **Оболочка** — Astro + Starlight. Страницы документации отдаются как статический HTML без JS.
- **Песочница** — один остров на Preact, подключается только там, где нужен.
- **Рендер мира** — один `<canvas>`. Здания и юниты никогда не становятся DOM-узлами.

Планируемая раскладка:

Модули оформлены как npm workspaces, зависимости строго в одну сторону:

```
core/    ВМ, мир, контент, метрики шрифта. Ноль зависимостей, тесты в ноде
render/  отрисовка мира и дисплея в canvas. Зависит от core
editor/  редактор блоков на Preact. Зависит от core
web/     сайт на Astro. Зависит от всего выше
docs/    рабочие документы проекта
tools/   генераторы дампов из исходников игры
```

`render` и `editor` не знают друг о друге: их склеивает страница. Это позволяет писать их
по отдельности.

## Правила работы

1. **Ядро не знает про UI.** Никаких обращений к DOM, canvas или таймерам браузера изнутри
   симуляции. Проверка: тесты ядра гоняются в ноде.
2. **Симуляция детерминированная.** Фиксированный тик, seeded RNG. Одинаковый вход — одинаковый
   выход, всегда.
3. **Каждая семантическая деталь закрывается тестом** со ссылкой на файл и строку в исходниках
   игры. Через полгода никто не вспомнит, почему в `equal` стоит эпсилон.
4. **Таблицы контента генерируются, а не пишутся руками.** Логические идентификаторы лежат
   в ассете `logicids.dat`, снимает их `tools/gen-content.mjs`.
5. **Границы v1 держим.** `radar`, юниты и инструкции мира отложены осознанно, см. `PLAN.md`.

## Генераторы

```bash
node tools/gen-content.mjs <путь-к-Mindustry>
```

Снимает таблицы контента из `core/assets/logicids.dat` в `core/data/logic-ids.json`. Результат
коммитится: без него сайт не соберётся, а пересоздать его можно только имея под рукой исходники
игры. Править файл руками нельзя.

```bash
node tools/gen-bundles.mjs <путь-к-Mindustry> [локали...]
```

Снимает официальные переводы игры в `core/data/i18n/<локаль>.json`: названия контента плюс
терминология логики — категории, описания инструкций, описания свойств `sensor` и `control`.
По умолчанию `en` и `ru`, в игре доступны 36 локалей.

```bash
node tools/gen-instructions.mjs <путь-к-Mindustry>
```

Снимает схему инструкций из `LStatements.java` в `core/data/instructions.json`: параметры,
их порядок, типы, значения по умолчанию, категории и 16 перечислений. Нужна редактору блоков.
Порядок параметров задаётся порядком объявления полей — именно его использует сериализация игры.

## Мультиязычность

Закладывается с первого дня, детали и причины — в `docs/decisions.md`.

1. **В ядре нет текста для пользователя.** Ошибки возвращаются кодами и структурированными
   данными; строки собираются на стороне сайта. Чинить это задним числом дорого.
2. **Имена инструкций, свойств и констант не переводятся.** `set`, `jump`, `@counter` — это язык,
   а не интерфейс.
3. **Урок переводится целиком, вместе с текстами проверок.** Сообщения проверок живут внутри
   локализованного урока, а не в отдельном словаре ключей.
4. **Структура симметрична:** `/ru/...` и `/en/...`, без «языка по умолчанию в корне».

## Библиотека arc

Часть семантики mlog живёт не в Mindustry, а в arc — там `Mathf`, `Angles`, `Rand`, `Simplex`
и разбор чисел. Игра закрепляет arc хешем коммита в `gradle.properties`, для v159.7 это
`archash=208a754044`. Пин такой же жёсткий, как у самой игры.

```bash
git clone --filter=blob:none --no-checkout --sparse https://github.com/Anuken/Arc.git
git -C Arc sparse-checkout set arc-core/src/arc/math arc-core/src/arc/util arc-core/src/arc/graphics
git -C Arc checkout 208a754044
```

Перенос лежит в `core/src/arc.js`. Трогать его без сверки с исходником нельзя: там всё написано
ради совпадения значений с игрой, а не ради красоты.

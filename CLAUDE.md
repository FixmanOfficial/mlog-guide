# mlog.guide

Интерактивный учебник и песочница по логике Mindustry (mlog), на английском и русском; английский —
язык по умолчанию. Документация языка плюс интерпретатор и симуляция мира прямо на странице.

Проект пишется с нуля. Семантика берётся из исходников игры, не из чужих реализаций.

## Контекст между сессиями

Работа рассчитана на много сессий. Перед началом читать:

| Файл | Что в нём |
| --- | --- |
| `PLAN.md` | Опись инструкций, граница v1, модель песочницы, порядок работ |
| `docs/decisions.md` | Журнал решений: что выбрали и почему. Дополнять при каждом новом решении |
| `docs/findings.md` | Семантические детали mlog, найденные в исходниках, со ссылками на Java |
| `docs/parity.md` | Реестр сверки с игрой: что из каждого класса перенесено, что расходится, что нет |
| `docs/todo.md` | Опись накопившихся работ: что осталось, в каком порядке и что отложено |
| `docs/course.md` | Полная опись уроков: все части, группы и уроки курса — по нему и идём |

Новое решение — строка в `docs/decisions.md`. Новая деталь поведения из исходников — строка
в `docs/findings.md` **и** тест. Найденное расхождение с игрой — строка в `docs/parity.md`,
и только потом правка кода: единица работы здесь класс игры, а не замеченная мелочь.

## Источник истины

**Mindustry v160.4**, тег зафиксирован. Обновление версии — отдельная осознанная задача, а не
«подтянуть последнее».

Исходники не лежат в репозитории. Развернуть локально:

```bash
git clone --depth 1 --branch v160.4 --filter=blob:none --sparse https://github.com/Anuken/Mindustry.git
git -C Mindustry sparse-checkout set core/src/mindustry/logic core/src/mindustry/world core/src/mindustry/content core/src/mindustry/type core/assets
```

Главное — `core/src/mindustry/logic/LExecutor.java` и `LStatements.java`.

## Лицензия

GPL-3.0, как у Mindustry. Списывать из Java напрямую можно и нужно — точность важнее оригинальности.

## Стек

- **Ядро** (ВМ + модель мира) — чистый JS, ноль зависимостей, ноль импортов из фреймворка.
  Запускается и тестируется в ноде.
- **Оболочка** — Astro + Starlight. Страницы документации отдаются как статический HTML без JS.
- **Песочница** — один остров на Preact, подключается только там, где нужен.
- **Рендер мира** — один `<canvas>`. Здания и юниты никогда не становятся DOM-узлами.

Планируемая раскладка:

Модули оформлены как npm workspaces, зависимости строго в одну сторону:

```
core/    ВМ, мир, контент, метрики шрифта. Ноль зависимостей, тесты в ноде
render/  отрисовка мира и дисплея в canvas. Зависит от core
editor/  редактор блоков на Preact. Зависит от core
web/     сайт на Astro. Зависит от всего выше
docs/    рабочие документы проекта
tools/   генераторы дампов из исходников игры
```

`render` и `editor` не знают друг о друге: их склеивает страница. Это позволяет писать их
по отдельности.

## Правила работы

1. **Ядро не знает про UI.** Никаких обращений к DOM, canvas или таймерам браузера изнутри
   симуляции. Проверка: тесты ядра гоняются в ноде.
2. **Симуляция детерминированная.** Фиксированный тик, seeded RNG. Одинаковый вход — одинаковый
   выход, всегда.
3. **Каждая семантическая деталь закрывается тестом** со ссылкой на файл и строку в исходниках
   игры. Через полгода никто не вспомнит, почему в `equal` стоит эпсилон.
4. **Таблицы контента генерируются, а не пишутся руками.** Логические идентификаторы лежат
   в ассете `logicids.dat`, снимает их `tools/gen-content.mjs`.
5. **Границы v1 держим.** `radar`, юниты и инструкции мира отложены осознанно, см. `PLAN.md`.
6. **Решает код игры, а не то, как выглядит на скриншоте.** Размеры снимать разбором спрайтов,
   цвета брать из `Pal`, стили из `Styles`. Если исходник расходится с описанием задачи —
   сделать как в исходнике и сказать об этом.

## Генераторы

Почти все генераторы читают исходники. Один — не читает, и это осознанно.

```bash
node tools/gen-dump.mjs <путь-к-Mindustry.jar>
```

Снимает спеки контента **из запущенной игры**: `core/data/unit-specs.json` (70 юнитов),
`core/data/block-specs.json` (447 блоков), `core/data/teams.json` и `core/data/materials.json`
(предметы и жидкости: цвет, твёрдость, стоимость, порядок для бура).

Вместе с блоком снимается его производство: `drillTime` и `tier` у буров, `craftTime`
и рецепт у фабрик, скорость у конвейеров и маршрутизаторов, а также потребление — предметы,
энергия, жидкости — из `block.consumers`.
Без этих чисел база в песочнице мёртвая, а разбором Java их не достать: рецепт лежит
не полем, а списком объектов `Consume`. Поднимает `ContentLoader` из
официального jar — то же самое, что делает игра при запуске, только без графики и звука, —
и читает значения из готовых объектов.

Разбором Java этого не сделать: половина чисел там не записана, а выводится в `init()`.
Дальность юнита собирается из скорости и времени жизни пуль каждого оружия — у кинжала это
146, и числа 146 в исходнике нет вовсе. Здоровье блока выводится из размера и состава,
вместимость — из размера корпуса. Регулярки дают на этом правдоподобные, но неверные числа.

Отдельно генератор пишет `core/data/stats.json` (2.7 МБ) — **полную опись характеристик**:
все публичные числа, флаги, перечисления и цвета каждого блока, юнита, предмета и жидкости,
включая то, что мы не моделируем: дальность и перезарядку турелей, потребление энергии, радиус
взрыва реактора. Собирается отражением, а не списком полей: список устарел бы молча. Из описи
исключены только служебные поля упаковки и локализации — переводы снимает `gen-bundles.mjs`.

В движок эта опись не идёт: `block-specs.json` и `unit-specs.json` остаются небольшими, потому
что попадают в сборку сайта, а `stats.json` нужен справочнику и читается при сборке страниц.

Цвет блока на карте лежит не в коде, а картинкой: `ContentLoader.loadColors` читает пиксель
с номером блока из `sprites/block_colors.png`. Генератор достаёт её из того же jar, иначе
`sensor @router @color` отдавал бы черноту всем блокам подряд.

Вместе с блоком снимается и энергия: кто её выдаёт, кто потребляет, кто проводит, мощность
генератора, дальность и предел связей мачты. Фильтр сырья при этом разворачивается в список:
сжигатель берёт «любое горючее», и предикат в описи не сохранить — генератор прогоняет его
по всем предметам, как это делает сама игра.

Вместе с блоком снимаются и правила постановки: `canReplace` и его поля (`replaceable`,
`alwaysReplace`, `subclass`, `groupAnyReplace`) плюс признак `chained` — звено ли это цепи
вроде конвейера. Признак берётся у построенного здания: `ChainedBuilding` реализует не блок,
а его `Building`, и в полях блока этого нет вовсе.

Нужен JDK 17 или новее (игра собрана под 17, на восьмёрке не запустится) — ищется сам,
в `JAVA_HOME`, среди установленных Adoptium и в PATH. Jar в репозиторий не кладём, качать
отсюда: `github.com/Anuken/Mindustry/releases/download/v160.4/Mindustry.jar`, 87 МБ.
Сам дампер — `tools/dump/ContentDump.java`.

**Версию jar генератор проверяет сам**: читает `version.properties` из архива и падает, если
сборка не та. Файл с именем `Mindustry.jar` в загрузках легко оказывается бетой другой сборки,
и тогда дамп молча разойдётся с исходниками — у сборки 155 нет блока `large-canvas`, и все
идентификаторы после него съезжают на единицу.

### Две версии вместо одной

Версии закреплены в `tools/version.mjs`, и их две:

| Константа | Что подписывает | Сейчас |
| --- | --- | --- |
| `GAME_VERSION` | всё, что снято с исходников: раскладки, схемы, палитры, переводы | v160.4 |
| `CONTENT_VERSION` | всё, что снято с jar: спеки контента, атласы, шрифт | v160.4 |

Сейчас они совпадают, и это обычное состояние. Разъехаться им позволено, когда в новой сборке
контент не менялся вовсе: тогда качать 87 МБ незачем, но и подписывать выгрузку версией,
которой её не снимали, нельзя. Проверять это диффом по `core/src/mindustry/content`
и `core/assets`, а не на глаз.

```bash
node tools/gen-content.mjs <путь-к-Mindustry>
```

Снимает таблицы контента из `core/assets/logicids.dat` в `core/data/logic-ids.json`. Результат
коммитится: без него сайт не соберётся, а пересоздать его можно только имея под рукой исходники
игры. Править файл руками нельзя.

```bash
node tools/gen-bundles.mjs <путь-к-Mindustry> [локали...]
```

Снимает официальные переводы игры в `core/data/i18n/<локаль>.json`: названия контента плюс
терминология логики — категории, описания инструкций, описания свойств `sensor` и `control`,
а также подсказки к подписям параметров (`radar.from`, `control.of`): у них нет общей
приставки, и отбираются они по списку инструкций.
По умолчанию `en` и `ru`, в игре доступны 36 локалей.

```bash
node tools/gen-instructions.mjs <путь-к-Mindustry>
```

Снимает схему инструкций из `LStatements.java` в `core/data/instructions.json`: параметры,
их порядок, типы, значения по умолчанию, категории и 16 перечислений. Нужна редактору блоков.
Порядок параметров задаётся порядком объявления полей — именно его использует сериализация игры.

## Мультиязычность

Закладывается с первого дня, детали и причины — в `docs/decisions.md`.

1. **В ядре нет текста для пользователя.** Ошибки возвращаются кодами и структурированными
   данными; строки собираются на стороне сайта. Чинить это задним числом дорого.
2. **Имена инструкций, свойств и констант не переводятся.** `set`, `jump`, `@counter` — это язык,
   а не интерфейс.
3. **Урок переводится целиком, вместе с текстами проверок.** Сообщения проверок живут внутри
   локализованного урока, а не в отдельном словаре ключей.
4. **Структура симметрична:** `/ru/...` и `/en/...`, без «языка по умолчанию в корне».
   Корень выбирает язык по браузеру, всех остальных отправляет на английский.
5. **Английский — язык по умолчанию.** Подписи меню пишутся по-английски, русские лежат
   переводами. Сцены примеров (`web/src/course/scenes/`) пишутся по-английски; для русской
   страницы имена и строки переписывает словарь `names.ru.js`. Тесты уроков гоняют русскую
   версию сцены — ту, с которой сверены числа в русских уроках.

## Библиотека arc

Часть семантики mlog живёт не в Mindustry, а в arc — там `Mathf`, `Angles`, `Rand`, `Simplex`
и разбор чисел. Игра закрепляет arc хешем коммита в `gradle.properties`, для v160.4 это
`archash=68a04fab6e`. Пин такой же жёсткий, как у самой игры.

```bash
git clone --filter=blob:none --no-checkout --sparse https://github.com/Anuken/Arc.git
git -C Arc sparse-checkout set arc-core/src/arc/math arc-core/src/arc/util arc-core/src/arc/graphics
git -C Arc checkout 68a04fab6e
```

Перенос лежит в `core/src/arc.js`. Трогать его без сверки с исходником нельзя: там всё написано
ради совпадения значений с игрой, а не ради красоты.

```bash
node tools/gen-metrics.mjs <путь-к-Mindustry>
```

Снимает размеры интерфейса в `core/data/metrics.json`: 86 чисел из `LCanvas`, `LStatement`,
`LogicDialog` и `BaseDialog`. Все они лежат в Java литералами — `height(38)`, `t.margin(6f)`,
`.size(24f).padRight(6)`. Каждое снимается своим шаблоном с якорем по соседнему коду, и если
шаблон перестал совпадать, генератор падает с именем размера: при обновлении версии игры это
единственный способ узнать, что раскладка поменялась.

```bash
node tools/gen-nine.mjs <путь-к-Mindustry>
```

Разбирает девятипатчи интерфейса в `core/data/nine-patches.json`: толщина рамки, срез угла,
цвета и прозрачность заливки. Вёрстка ссылается на эти числа переменными CSS, которые ставит
`editor/src/nine.js`. Так и выяснилось, что кнопка в игре не прямоугольная.

```bash
node tools/gen-pal.mjs <путь-к-Mindustry>
```

Снимает палитру из `graphics/Pal.java` в `core/data/pal.json`: 111 цветов по именам. Цвета
глазом не проверяются — `#454545` и `#4d4d4d` рядом не отличить, — поэтому каждая цветовая
константа в коде сверяется с этой таблицей тестом.

```bash
node tools/gen-globals.mjs <путь-к-Mindustry>
```

Снимает опись встроенных переменных из `GlobalVars.init()` в `core/data/globals.json`: 32
переменные в 5 разделах, в том же порядке, в каком их показывает окно игры. Описания к ним
лежат в бандлах под ключами `lglobal.` и снимаются `gen-bundles.mjs`.

```bash
node tools/gen-access.mjs <путь-к-Mindustry>
```

Снимает таблицу свойств `LAccess` в `core/data/access.json`: 77 свойств — у кого каждое
читается, число это или объект, кому его пишет `setprop`. Имена свойств игра переводит,
а вот **у кого** свойство работает не написано нигде: это `switch` в коде, и их полсотни.

Общие лежат у восьми носителей (`Block`, `BuildingComp`, `UnitType`, `UnitComp`, `Item`,
`Liquid`, `Team`, `BulletComp`), остальные — в конкретных классах блоков: `@ammo` только
у турели, `@progress` у бура и фабрики, `@memoryCapacity` у ячейки памяти. Класс блока
и вся цепочка его предков приходят из выгрузки (`javaClasses` в `block-specs.json`),
по ней 42 переопределения разворачиваются в списки блоков.

```bash
node tools/gen-icons.mjs <путь-к-Mindustry>
```

Снимает таблицу иконок из `core/assets/fonts/icon.ttf` в `core/data/icons.json`: 136 имён
и кодов символов. Иконки в игре — глифы этого шрифта, а не картинки, поэтому картинок не нужно
вовсе: подключается тот же шрифт, выводится символ по коду.

```bash
node tools/gen-font.mjs <путь-к-Mindustry> [файл]
```

Вырезает из основного шрифта игры латиницу, кириллицу и знаки препинания в `editor/assets/ui.woff2`:
344 глифа и 23 КБ вместо 42 515 глифов и 3.5 МБ. Без родного шрифта редактор перестаёт быть
похожим на редактор из игры.

```bash
node tools/gen-webfonts.mjs <путь-к-Mindustry>
```

Перекладывает остальные шрифты игры в WOFF2: иконки, моноширинный и шрифт дисплея. Формат
пишет `tools/woff2.mjs` — таблицы без преобразований, сжатые brotli из самой ноды. Шрифт
дисплея весит 5 КБ вместо 41.

```bash
node tools/gen-sprites.mjs <путь-к-Mindustry.jar>
```

Собирает иконки контента в атлас `editor/assets/content.png` и указатель `core/data/sprites.json`:
348 предметов, жидкостей, блоков и юнитов. Нужен меню выбора у `sensor` и инструкции `draw image`.

Иконка в игре — это `UnlockableContent.fullIcon`, и ищется он по цепочке имён, первое из которых
`<тип>-<имя>-full`: картинка, собранная упаковщиком из слоёв. У дуо это ствол поверх корпуса,
а у жидкостей исходного файла нет вовсе — `liquid-water` рисует сам упаковщик. Поэтому берётся
цепочка целиком, как в `loadIcon`.

Сторона ограничена 48 точками с сохранением пропорций: полное разрешение (у иных блоков 400)
утроило бы атлас, а меню показывает иконки по 40 и вся сторона большого дисплея — 176.

```bash
node tools/gen-blocks.mjs <путь-к-Mindustry.jar>
```

Собирает спрайты блоков мира в атлас `render/assets/blocks.png` и указатель
`core/data/block-sprites.json`: 379 спрайтов — всё, что игра разрешает строить, плюс четыре
привилегированных блока, пометки вроде уголков выделения и накладки команд (`<имя>-team`,
а у команд с палитрой ещё `<имя>-team-<команда>`): без них хранилище и ядро выходят белыми. Отдельно от `gen-sprites.mjs`
потому, что тот делает иконки и ограничивает их 48 точками, а на карте спрайт рисуется
своим размером: у логического процессора 64, у большого дисплея 192. Уменьшенной иконкой
блок на карте расплывается.

Имя спрайта не всегда совпадает с именем блока, и цепочка та же, что у `loadIcon`:
`<имя>`, потом `<имя>-preview` у сборных турелей, потом `<имя>-0-0` у конвейеров
и `<имя>-top-0` у труб — их спрайт разбит на соединения и кадры, а иконкой служит прямой
участок. У конвейеров сверх иконки берётся вся таблица соединений — пять видов стыковки
на четыре кадра хода ленты: на карте рисуется она, и без неё лента на повороте оставалась
бы прямой.

### Картинки берутся из атласа игры, а не из исходных спрайтов

Три генератора — блоки, юниты, местность — читают **упакованный атлас игры** из того же jar,
что и дамп спеков: `sprites/sprites.aatls` плюс четыре страницы PNG. Разбор атласа лежит
в `tools/atlas.mjs`, чтение jar как zip — в `tools/zip.mjs`, укладка в наш атлас — в `tools/pack.mjs`.

Причина простая: упаковщик игры не только складывает спрайты, он часть их **создаёт**.
Юнитам запекается обводка (`Pixmaps.outline`, радиус 3, цвет `Pal.darkerMetal`), полам
собираются листы мягких краёв `<имя>-edge`. В `assets-raw` этого нет вовсе. Рисуя исходниками,
мы тихо расходились с игрой: у кинжала рисунка 40 на 24 точки, а в атласе 48 на 32.

Отдаём при этом свои атласы, а не игровые: у игры это 8 МБ на четырёх страницах и 5143 региона,
странице нужно полтысячи. Правило — **источник игровой, упаковка своя**.

```bash
node tools/gen-terrain.mjs <путь-к-Mindustry.jar>
```

Собирает местность в атлас `render/assets/terrain.png` и указатель `core/data/terrain-sprites.json`:
полы, руды, статичные стены со всеми вариантами плиток и листы краёв. Вариант плитки выбирается
не случайно, а `Mathf.randomSeed` от координат тайла — поэтому карта не мельтешит при перерисовке.
Полы с плиточной и автотайловой раскладкой (`metal-tiles`, вода) пропущены: у них своя механика,
см. `docs/parity.md`.

```bash
node tools/gen-units.mjs <путь-к-Mindustry.jar>
```

Собирает спрайты юнитов в атлас `render/assets/units.png` и указатель `core/data/unit-sprites.json`:
67 юнитов: корпус с обводкой, накладка `-cell` цветом команды, а у мехов ещё ноги `-leg`
и основание `-base`. Спрайты не квадратные (у скипетра 170 на 140), поэтому атлас свой,
а не общий с блоками. Огню двигателей спрайт не нужен — игра рисует его двумя кругами.

Каталог `core/assets-raw/sprites` после перехода на атлас не нужен вовсе — в разреженный чекаут
он и не входит.

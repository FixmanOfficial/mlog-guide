# Детали семантики mlog

Каталог поведения, которое нельзя угадать — только вычитать в исходниках Mindustry **v159.7**.
Пути даны от `core/src/mindustry/`.

Правило: каждая строка отсюда закрывается тестом. Колонка «тест» заполняется, когда тест написан.
Ссылаться на пункты по разделу и формулировке, не по номеру — номера смещаются.

## Операции и сравнения

| Деталь | Источник | Тест |
| --- | --- | --- |
| `equal` и `notEqual` сравнивают с эпсилоном `0.000001`, а не точно. Для объектов — отдельная ветка через `Structs.eq` | `logic/LogicOp.java`, `logic/ConditionOp.java` | — |
| `strictEqual` в enum — заглушка (`(a, b) -> 0`), реальная логика в исполнителе | `logic/LogicOp.java` | — |
| Битовые операции 64-битные: `(long)a >>> (long)b`. Наивный JS даст 32 бита и разойдётся с игрой на больших числах | `logic/LogicOp.java` | — |
| `not` / `flip` — это `~(long)a`, тоже 64 бита | `logic/LogicOp.java` | — |
| Тригонометрия в **градусах**: `sin` умножает на `doubleDegRad`, `asin` на `doubleRadDeg` | `logic/LogicOp.java` | — |
| `rand` берёт seeded-генератор `GlobalVars.rand`, а не системный | `logic/LogicOp.java`, `logic/GlobalVars.java:28` | — |
| `noise` — это `Simplex.raw2d(0, x, y)`. Нужна реализация симплекс-шума, совпадающая с arc | `logic/LogicOp.java` | — |
| `angle`, `angleDiff`, `len` считаются во `float` через `Angles`/`Mathf`, а не в `double`. Точность отличается от прямого `Math.hypot` | `logic/LogicOp.java` | — |

## Переменные и константы

| Деталь | Источник | Тест |
| --- | --- | --- |
| **Логические идентификаторы не выводятся из порядка регистрации контента.** Игра читает готовое соответствие из ассета `logicids.dat`, собираемого `ImagePacker` при сборке. Файл фиксирует идентификаторы между версиями, чтобы не ломались старые схемы | `logic/GlobalVars.java:158-184` | — |
| Формат `logicids.dat` — `DataInputStream`: для каждого типа `short` количество, затем столько же `readUTF()`. Порядок типов строго `block`, `unit`, `item`, `liquid` | `logic/GlobalVars.java:26,162-176` | ✓ разбор в `tools/gen-content.mjs` |
| Константы `@copper`, `@router` и прочие строятся на старте обходом зарегистрированного контента — это отдельный механизм от логических идентификаторов | `logic/GlobalVars.java:110-151` | — |
| Константы `@blockCount`, `@unitCount`, `@itemCount`, `@liquidCount` берутся из количеств в том же `logicids.dat` | `logic/GlobalVars.java:168` | — |

| Есть алиас `π` для `@pi` — «for the cool kids» | `logic/GlobalVars.java:60` | — |
| `@time` считается от `@tick`, а не от системных часов — в комментарии прямо сказано, что прошлый вариант был плохой идеей | `logic/GlobalVars.java:188` | — |

## Исправленные заблуждения

Оставлено намеренно: эти утверждения выглядят правдоподобно и легко появляются снова.

| Неверно | На самом деле |
| --- | --- |
| «Логические идентификаторы зависят от порядка регистрации контента, поэтому дамп надо снимать с `content/*.java`» | Идентификаторы лежат в `logicids.dat` и стабильны между версиями. Парсить Java не нужно и вредно — получится другой порядок |

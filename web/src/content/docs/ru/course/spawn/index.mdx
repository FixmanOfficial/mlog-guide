```
spawn @dagger 9 5 90 @sharded новый
```

Кинжал появляется на клетке `9 5` — готовый, с полным здоровьем, без всякого завода.
В примере программа делает это, пока их не станет трое, и останавливается.

| Поле | Что в нём |
| --- | --- |
| первое | тип юнита: `@dagger`, `@poly`, `@flare` |
| второе и третье | координаты в клетках |
| четвёртое | поворот в градусах: 90 — вверх, 0 — вправо |
| пятое | команда: `@sharded`, `@crux`, `@derelict` |
| шестое | куда положить **созданного юнита** |

Шестое поле — самое полезное: юнит приходит объектом, и с ним сразу можно работать.
Правда, не любой инструкцией:

```
spawn @dagger 9 5 90 @sharded новый
ubind новый
ucontrol move 20 5 0 0 0
```

Мировому процессору такая привязка удаётся и к чужому юниту — это его привилегия.

<Card kind="note">
Поворот на появление влияет мало: юнит тут же начнёт разворачиваться туда, куда ему нужно.
Заметен он только у наземных, которым разворот стоит времени.
</Card>

## Счётчика тут нет

<Card kind="error">
**`spawn` не считает ни ресурсов, ни предела юнитов.** Каждая итерация программы создаёт
нового — а итераций у мирового процессора до тысячи в тик.

Строка `spawn` без всякой проверки за секунду наплодит тысячи кинжалов и положит игру.
Это самая частая ошибка в сценариях на мировом процессоре, и заметна она сразу.
</Card>

Поэтому появление всегда **чем-то ограничивают**:

- **посчитать, сколько уже есть.** Как в примере: <Lesson lesson="query">`query`</Lesson>
  по области, `sensor @size`, и появление только если мало;
- **сделать один раз.** Переменная-признак или <Lesson lesson="setflag">глобальный флаг</Lesson>:
  создали — записали, потом проверяем;
- **по времени.** `@time` и сравнение со сроком: волна раз в полминуты.

```
query circle unit @sharded 9 5 5 0
sensor сколько @queries @size
jump 0 greaterThanEq сколько 3
spawn @dagger 9 5 90 @sharded новый
```

Четыре строки — и на карте всегда ровно три кинжала: погиб один, на его место придёт новый.

<Card kind="note">
Предел юнитов из правил игры (`unitCap`) инструкция тоже не смотрит — она сильнее правил.
Если предел важен для сценария, его проверяют сами: `@unitCount` тут не поможет, это длина
таблицы типов, а не число живых юнитов.
</Card>

<Card kind="recap">
- `spawn тип x y поворот команда результат` создаёт юнита мгновенно.
- Созданный приходит объектом в последнее поле.
- Ни ресурсов, ни предела юнитов инструкция не проверяет.
- Появление обязательно ограничивают: счётом, признаком или временем.
</Card>

<Card kind="task">
Поменяйте в примере `3` на `8` в строке `jump`: кинжалов на карте станет восемь,
и программа снова остановится.

Потом замените `@sharded` на `@crux` в строке `spawn`: счёт своих больше не сойдётся —
`query` ищет своих, а появляются вражеские, и программа не остановится никогда.
</Card>

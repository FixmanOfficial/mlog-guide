```
print "Держите оборону!"
message announce 3 @wait
```

Текст собирается тем же <Lesson lesson="print/buffer">`print`</Lesson>, что и для блока
сообщений, а `message` отправляет его **на экран игрока**. Через три секунды объявление
пропадает, и программа показывает его снова: счётчик `показов` растёт примерно раз
в три секунды.

| Поле | Что в нём |
| --- | --- |
| первое | вид сообщения |
| второе | сколько секунд держать |
| третье | куда положить ответ: получилось или нет |

## Четыре вида

| Вид | Как выглядит |
| --- | --- |
| `announce` | крупный текст посреди экрана |
| `notify` | строка сверху, как о постройке ядра |
| `toast` | всплывающая подсказка, короткая и мелкая |
| `mission` | задача партии: висит в углу, пока её не сменят |

`mission` стоит особняком: это не всплывающее сообщение, а **текст задания**. Он никуда
не исчезает и никого не ждёт — просто заменяет прежний.

<Card kind="note">
Объявление и всплывающая подсказка делят одно место на экране, а уведомление — своё.
Поэтому `notify` проходит даже тогда, когда `announce` ещё висит.
</Card>

## Занятый экран

<Example client:load scene={BUSY} world={true} />

Два сообщения подряд: первое проходит (`первое` равно единице), второе — нет
(`второе` равно нулю). Место занято, и программа об этом узнаёт.

Важное: **при отказе буфер не чистится**. Текст «И ещё одна» остаётся в буфере печати
и уйдёт на экран со следующей удачной попыткой. Ничего не теряется.

<Card kind="error">
**Это ловушка для программ, которые печатают каждую итерацию.** Пока экран занят, каждая
итерация добавляет в буфер ещё одну копию текста — и когда место освободится, игрок увидит
слипшуюся простыню из сотни повторов.

Поэтому либо печатают только перед удачной отправкой, либо оставляют в поле ответа `@wait`.
</Card>

## `@wait`: программа ждёт своей очереди

В поле ответа по умолчанию стоит `@wait` — и это не просто имя переменной. Пока оно там,
занятый экран **задерживает программу** на этой строке: счётчик откатывается назад, тик
уступается, и на следующем тике попытка повторяется.

```
print "Держите оборону!"
message announce 3 @wait
op add показов показов 1
```

Именно так работает первый пример: `print` не успевает повториться, потому что программа
стоит на строке с `message`, а не пробегает итерацию за итерацией.

<Card kind="note">
`@wait` — старое поведение инструкции, оставленное ради совместимости: поля ответа раньше
не было вовсе, и `message` всегда ждал. Поставьте свою переменную — и ожидание сменится
отказом, который надо проверять самому.
</Card>

<Card kind="recap">
- `message вид срок ответ` отправляет буфер печати на экран игрока.
- Видов четыре: `announce`, `notify`, `toast` и `mission`.
- `mission` — текст задачи, он не исчезает сам.
- Занятый экран отвечает нулём, а буфер при этом остаётся целым.
- `@wait` в поле ответа заставляет программу ждать вместо отказа.
</Card>

<Card kind="task">
В первом примере поменяйте `announce` на `notify`: сообщение переедет наверх — это другое
место на экране, и занято оно отдельно.

Во втором примере поменяйте вид второго сообщения на `notify`: оба пройдут, потому что
уведомление и объявление друг другу не мешают.
</Card>

В поле `ubind` можно поставить не только тип, но и **самого юнита** — того, который лежит
в переменной. Тогда привязка не идёт по кругу, а возвращается ровно к нему.

<Example client:load scene={REMEMBER} world={true} />

```
ubind @poly
set мой @unit
...
ubind мой
```

Программа привязалась, запомнила юнита в обычной переменной, привязалась ещё дважды —
а потом вернулась к запомненному. Переменная `тотЖе` подтверждает: в `@unit` снова он.

## Зачем возвращаться к тому же

Перебор годится, когда всем юнитам нужно одно и то же. Как только у юнита появляется
**личное дело** — этот везёт медь, тот чинит стену, третий сторожит проход, — перебор
начинает мешать: на каждой итерации команда достаётся другому, и ни один не доводит дело
до конца.

Тогда юнита запоминают:

- в переменной — если процессор занят им одним;
- в <Lesson lesson="write/cells">ячейке памяти</Lesson> — если юнитов несколько и у каждого
  своё занятие;
- во флаге самого юнита — если пометку должны видеть и другие процессоры.

<Card kind="note">
Переменные процессора не переживают правку программы, а ячейка памяти переживает. Поэтому
отряд, разобранный по обязанностям, обычно хранят в ячейке: иначе одна правка — и все
юниты разом забывают, кто чем занимался.
</Card>

## Юнит гибнет, переменная помнит

<Example client:load scene={LOST} world={true} />

Вспышка стоит под огнём чужой турели и через несколько секунд погибнет. Смотрите
за переменными: `мёртв` станет единицей, а `живых` покажет, что привязываться больше
не к кому.

Вот что при этом происходит:

- юнит выбывает из перебора — `ubind @flare` сразу начинает отдавать пустоту;
- **переменная продолжает указывать на покойника**. Она не обнуляется сама;
- `sensor мёртв мой @dead` отвечает единицей — это и есть способ проверить.

<Card kind="error">
**Запомненного юнита обязательно проверяют.** Программа, которая раз в минуту достаёт
из ячейки «своего» юнита и командует им, будет годами командовать мёртвым: команды тихо
уходят в никуда, а на карте ничего не происходит.

```
sensor мёртв мой @dead
jump 8 equal мёртв 1
```

Не нашлось живого — берут нового перебором и записывают на его место.
</Card>

## Отпустить юнита

Привязка не отдаёт команд сама по себе, а вот `ucontrol` — отдаёт, и юнит после неё
десять секунд слушается процессора вместо собственного разума. Вернуть его к своим делам
можно сразу:

```
ucontrol unbind 0 0 0 0 0
```

Это не «отвязать от `@unit`» — переменная останется прежней. Это «перестать им управлять»:
юнит возвращается к обычному поведению, а процессор может заняться следующим.

<Card kind="recap">
- `ubind переменная` привязывается к конкретному юниту, а не к следующему по списку.
- Юнита с личным делом запоминают: в переменной, в ячейке или во флаге.
- Гибель не обнуляет переменную — она обнуляет только перебор.
- Проверка живости — `sensor @dead` у самого юнита.
- `ucontrol unbind` возвращает юнита его собственному разуму.
</Card>

<Card kind="task">
В первом примере поставьте `ubind @poly` вместо `ubind мой` в предпоследней строке:
`тотЖе` станет нулём — перебор выдал следующего юнита, а не запомненного.

Во втором примере уберите первую строку `jump 3 notEqual мой null`. Теперь программа
каждую итерацию берёт юнита заново — и после гибели вспышки `мой` станет пустым, а `мёртв`
обнулится: спрашивать `@dead` станет не у кого.
</Card>

Две строки, отличающиеся одним словом: первая находит **вражескую** турель на клетке 18,

| Поле | Что в нём при поиске здания |
| --- | --- |
| первое | `building` |
| второе | **метка**: что это за здание по роли |
| третье | `true` — чужое, `false` — своё |
| четвёртое | предмет — этому виду поиска не нужен |
| пятое и шестое | координаты найденного |
| седьмое | нашлось или нет |
| восьмое | **само здание** объектом |

## Метки: роль вместо названия

Искать «двойную турель» или «контейнер» нельзя — можно искать здание с нужной **меткой**.
Метки расставлены заранее, в самой игре, и их десять:

| Метка | Кто ею помечен |
| --- | --- |
| `core` | ядро |
| `storage` | контейнер, хранилище |
| `generator` | всё, что вырабатывает энергию |
| `turret` | любая турель |
| `factory` | фабрики: плавильни, прессы, смесители |
| `repair` | ремонтная точка |
| `battery` | батарея |
| `reactor` | реактор |
| `drill` | любой бур |
| `shield` | проектор поля |

Метка у здания может быть не одна: ториевый реактор помечен и как `generator`,
и как `reactor` — искать его можно и так, и так.

<Card kind="note">
У конвейера, стены, сортировщика и прочей мелочи меток нет вовсе — такие здания `ulocate`
не найдёт никогда. Метки существуют не для логики: по ним игра наводит юнитов и волны,
а логике их просто разрешили читать.
</Card>

## Восьмое поле: само здание

`ulocate` отдаёт не только координаты, но и здание объектом — и это самое ценное. Дальше
с ним работают как с любым зданием:

```
ulocate building core false @copper x y нашлось ядро
sensor меди ядро @copper
sensor цело ядро @health
```

Связь с этим зданием не нужна: `sensor` читает и не связанные блоки. А вот `control` —
нет, ему связь обязательна.

<Card kind="error">
**Здание приходит объектом не всегда.** Чужое здание отдаётся объектом, только если юнит
до него дотягивается — дальностью оружия или дальностью стройки. Если оно дальше,
координаты придут, а в восьмом поле будет пустота.

Со своими проще: свои отдаются объектом всегда, на любом расстоянии.
</Card>

## Координата здания — не всегда целая

Посмотрите на `складX` в примере: `10.5`, хотя контейнер стоит на десятой клетке.

Так и должно быть. У блока с чётной стороной — 2×2, 4×4 — центр приходится не на середину
клетки, а на её угол, и координаты у него получаются с половинкой. `ulocate` отдаёт именно
центр здания, как и `sensor @x`.

Для `ucontrol move` это даже удобнее: юнит подлетит к середине склада, а не к его углу.

<Card kind="recap">
- `ulocate building` ищет ближайшее здание с нужной **меткой**, а не с нужным названием.
- Меток десять: ядро, склад, генератор, турель, фабрика, ремонт, батарея, реактор, бур, щит.
- Третье поле выбирает, чьё здание искать: чужое или своё.
- Восьмое поле отдаёт здание объектом — и его сразу можно читать `sensor`.
- Чужое здание достаётся объектом только в пределах досягаемости юнита.
- У блока с чётной стороной координата центра выходит с половинкой.
</Card>

Потом в третьей строке поставьте `true` вместо `false`: своя турель искаться перестанет,

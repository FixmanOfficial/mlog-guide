```
ubind @mono
ulocate ore core true @copper рудаX рудаY нашлось здание
ucontrol mine рудаX рудаY 0 0 0
```

Две строки находят медь и отправляют моно копать её. На этой карте ближайшая медь лежит
на клетке `12 7` — туда юнит и летит, а `груз` начинает расти.

| Поле | Что в нём при поиске руды |
| --- | --- |
| первое | `ore` |
| второе | метка блока — при поиске руды не используется |
| третье | «врага ли искать» — тоже не используется |
| четвёртое | **предмет**: `@copper`, `@lead`, `@titanium` |
| пятое и шестое | куда положить координаты клетки |
| седьмое | нашлось или нет |
| восьмое | здание — у руды его нет, придёт пустота |

Полей у `ulocate` восемь на все четыре вида поиска сразу, и лишние просто не смотрят.
В редакторе игры это видно наглядно: часть полей гаснет, стоит выбрать `ore`.

## Ищется ближайшая к юниту

<Example client:load scene={LEAD} world={true} />

На этой же карте есть и свинец — в другой стороне. Поиск отдаёт `5 3`, потому что считает
расстояние **от юнита**, а не от процессора и не от ядра.

Значит, два юнита с одной и той же программой полетят к разным залежам: каждый к своей
ближайшей. Отдельно разводить их по карте не надо.

<Card kind="error">
**Руды может не быть вовсе.** Титана на этой карте нет, и `ulocate ore ... @titanium`
отвечает нулём в поле «нашлось», а координаты оставляет от прошлого поиска.

Поэтому `нашлось` проверяют **до** того, как отдавать команду: `ucontrol mine` с чужими
координатами отправит юнита копать пустое место.

```
ulocate ore core true @titanium x y нашлось здание
jump 0 equal нашлось 0
ucontrol mine x y 0 0 0
```
</Card>

## Что считается рудой

Поиск смотрит на **наложение** — тот слой карты, где лежат руды, — и ищет клетку,
из которой добывается нужный предмет. Песок в счёт тоже идёт: он не руда, но копается.

<Card kind="note">
Найденная клетка не проверяется на то, **по зубам** ли она юниту. Моно найдёт залежь титана
и полетит к ней, а копать не сможет. Уровень добычи — забота программы: либо ищут только
то, что юнит умеет, либо проверяют `@mining` после команды.
</Card>

<Card kind="recap">
- `ulocate ore` ищет ближайшую к **юниту** клетку с нужной рудой.
- Предмет задаётся четвёртым полем; остальные поля этому виду поиска не нужны.
- Координаты отдаются в клетках и годятся прямо для `ucontrol mine`.
- Нет такой руды на карте — в «нашлось» ноль, а координаты остаются старыми.
- Найденное не проверяется на уровень добычи юнита.
</Card>

<Card kind="task">
В первом примере поменяйте `@copper` на `@lead`: моно развернётся и полетит в другую
сторону — к свинцу на клетке `5 3`.

Потом поставьте `@titanium`: `нашлось` станет нулём, координаты так и останутся нулями,
и `ucontrol mine 0 0` отправит юнита копать угол карты. Он туда даже не полетит — просто
ничего не произойдёт, и разбираться придётся по переменным. Это и есть та ошибка,
от которой спасает проверка «нашлось».
</Card>

В `jump` помещается ровно одна проверка: два значения и одно сравнение. Ни «и», ни «или»,
ни «иначе если» в нём нет — и не появится. Зато переходов можно поставить несколько подряд,
и этого хватает на всё.

## «И» — это два перехода подряд

Условие «включено **и** запаса хватает» пишется двумя строками, и обе ведут в одно
и то же место — мимо работы:

```
jump 8 equal включено 0
jump 8 lessThan запас 10
```

Обратите внимание: проверки **перевёрнуты**. `jump` уводит выполнение, значит уводить его
надо тогда, когда условие работы **не** выполнено. Это главная причина, по которой чужие
программы на mlog читаются тяжело, и привыкнуть к ней стоит сразу.

<Card kind="note">
Есть и второй способ: сложить условие в переменную через `op land` и проверить её одним
переходом. Он читается легче, но стоит лишних инструкций и не умеет останавливаться
на первой же неудачной проверке. Для двух проверок обычно берут переходы, для сложного
условия — `op`.
</Card>

## «Или» — два перехода в одно место

Перевёрнутых проверок здесь не нужно: каждый переход сам по себе достаточен.

```
jump 12 greaterThan враговРядом 0
jump 12 lessThan здоровье 200
```

Программа уйдёт на строку 12, если случилось **хотя бы одно** из двух.

## Ранний выход вместо вложенности

<Example client:load scene={GUARD} world={false} />

Вот та же пара проверок целиком. Всё, что должно сорвать работу, проверяется **в начале**,
и каждая проверка уводит в конец:

```
jump 8 equal включено 0
jump 8 lessThan запас 10
set выдать 5
op sub запас запас выдать
set сделано 1
stop
set сделано 0
```

Такой приём называют **ранним выходом**, а сами проверки — **охраной**. Работа остаётся
одним ровным куском, без ступенек.

Соблазн написать наоборот — «если включено, то если запаса хватает, то…» — приводит
к лесенке из переходов, где каждая ветка ведёт на свою строку. В тексте это ещё читается,
а в блоках превращается в клубок стрелок.

<Card kind="note">
**Номер строки в `jump` можно не писать вовсе.** В текстовой записи есть метки: строка
вида `конец:` не занимает номера, а `jump конец ...` ведёт на неё.

```
ещёРаз:
op add счёт счёт 1
jump ещёРаз lessThan счёт 5
```

Это обычная часть языка, а не выдумка внешних редакторов: метки понимает сам разбор игры.
Вставленная в середину строка после этого ничего не ломает — цель привязана к метке,
а не к номеру. Подробнее — в уроке <Lesson lesson="advanced/labels">«Метки»</Lesson>.

В блоках меток нет и не нужно: там цель — стрелка на сам блок, и она едет вместе с ним.
</Card>

## Выйти из цикла досрочно

<Example client:load scene={BREAK} world={true} />

Цикл ищет в ячейке первое непустое место — и прекращает перебор, как только нашёл:

```
read значение cell1 адрес
jump 7 notEqual значение 0
op add адрес адрес 1
jump 1 lessThan адрес 64
set найдено -1
stop
set найдено адрес
```

Переход из середины цикла на строку **после** него и есть досрочный выход. Программа
остановится на адресе 3, где лежит `42`, а не пройдёт все шестьдесят четыре места впустую.

Строка `set найдено -1` — то, что случится, если цикл дошёл до конца и ничего не нашёл.
Ответ «не нашлось» стоит готовить всегда: без него переменная останется с прошлой итерации,
и программа примет старую находку за новую.

## Пропустить шаг

<Example client:load scene={SKIP} world={false} />

Обратный случай: шаг цикла не нужно делать, но и выходить рано. Переход ведёт не наружу,
а **на увеличение счётчика**:

```
op mod остаток счёт 2
jump 4 notEqual остаток 0
op add итог итог счёт
op add счёт счёт 1
jump 1 lessThan счёт 10
```

В сумму попадают только чётные числа — итог выходит `20`. Нечётные цикл проматывает,
не трогая сумму.

<Card kind="error">
**Пропуск не должен перепрыгивать счётчик.** Если переход уведёт выше строки `op add счёт
счёт 1`, счётчик перестанет расти, и цикл станет вечным. Программа не сломается и не выдаст
ошибки — она просто навсегда застрянет на одном значении.
</Card>

<Card kind="recap">
- В `jump` одна проверка; «и» — это несколько переходов подряд в одно место.
- Для «и» проверки переворачивают: уводим, когда условие работы не выполнено.
- «Или» собирается из переходов без переворота.
- Ранний выход держит программу плоской: охрана в начале, работа одним куском.
- Выход из цикла — переход на строку после него, пропуск шага — переход на счётчик.
- Ответ «не нашлось» готовят заранее, иначе останется прошлый.
</Card>

<Card kind="task">
В первом примере поставьте `set включено 0` и запустите: работа не выполнится вовсе —
`сделано` станет нулём, а `запас` останется сороковым.

Во втором примере поменяйте содержимое ячейки так, чтобы непустых мест не было вовсе,
и посмотрите на `найдено`: там окажется `-1` — тот самый заранее приготовленный ответ.
</Card>

Ветвление ради одного значения — самая частая трата строк в mlog. «Если меди хватает, положи
в переменную единицу, иначе ноль» — это `jump`, два `set` и ещё один `jump`, чтобы ветки
не слились. Четыре строки, чтобы записать одно число.

`select` делает то же самое одной строкой.

<Example client:load scene={CHOICE} world={true} />

Нажмите «шаг» четыре раза. В контейнере 120 меди, поэтому `хватает` станет единицей,
`надпись` — строкой «хватает», а `сколькоБрать` — сотней.

## Как читается строка

В блоке она подписана словами, а не знаками:

```
итог = если медь >= 100 тогда 1 иначе 0
```

Полей шесть: куда положить, условие, два значения для сравнения и два значения на выбор.
Условия те же восемь, что у `jump`, и на кнопке у них те же знаки — `==`, `===`, `not`
и остальные из [таблицы](/ru/course/jump/branch/).

<Card kind="note">
Слова «если», «тогда» и «иначе» — перевод: без него на кнопках будет `if`, `then`, `else`.
Как и везде, переводятся только надписи, а сама программа остаётся английской.
</Card>

## Выбирают значение, а не действие

Это главное ограничение, и оно же объясняет, когда `select` не годится.

Обе половины — **значения**, которые уже готовы: числа, строки, переменные, объекты.
Инструкция не выполняет одну из двух веток — ей нечего выполнять, она просто берёт одно
из двух и кладёт в переменную.

| Нужно | Чем |
| --- | --- |
| положить одно из двух чисел | `select` |
| включить один блок из двух | `jump`: это действие, а не значение |
| посчитать по-разному в двух случаях | `jump`: вычисление это отдельная строка |
| выбрать, что записать в память | `select`, а `write` уже общий |

<Card kind="error">
Вычисления в полях `select` не спрятать: `итог = если … тогда a+1 иначе a-1` записать нельзя,
потому что `a+1` — не значение, а операция. Считают заранее, в двух строках `op`, а `select`
выбирает уже посчитанное. Если считать дорого, дешевле оказывается `jump`: он-то как раз
лишнее вычисление пропустит.
</Card>

## Третья строка примера

`select сколькоБрать lessThan медь 100 медь 100` — приём, который стоит запомнить: **ограничить
число сверху**. Если меди меньше сотни, взять сколько есть, иначе — ровно сотню.

То же самое умеет `op min`, и в этом случае он короче. Но `select` не ограничен числами:
так же выбирают предмет, здание или строку, а `min` работает только с числами.

<Card kind="recap">
- `select` кладёт в переменную одно из двух значений по условию.
- Условия те же, что у `jump`, и надписи на кнопках те же.
- Обе половины — готовые значения: ни вычислений, ни действий там не бывает.
- Когда выбирают путь, а не значение, нужен `jump`.
- Ограничение числа сверху и снизу — частый случай, где `select` заменяет ветку целиком.
</Card>

<Card kind="task">
Поменяйте во второй строке условие на `lessThan` и пройдите пример заново: `хватает` станет
нулём, хотя меди по-прежнему 120. Условие перевернулось, а значения остались на местах —
первое по-прежнему для «верно».

Потом впишите в третью строку вместо `"мало"` имя `медь`. Строка `«хватает»` останется
строкой, а вторая половина станет числом: `select` не требует, чтобы обе половины были
одного вида.
</Card>

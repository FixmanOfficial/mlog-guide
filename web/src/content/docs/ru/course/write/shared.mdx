У процессоров нет общих переменных. Совсем: `медь` в одном и `медь` в другом — два разных
значения, и узнать чужое нельзя ничем. Зато ячейка памяти — обычный блок, и подключиться
к ней могут оба.

<Example client:load scene={SHARED} world={true} />

На карте два процессора. Верхний спрашивает склад и кладёт ответ в ячейку; нижний берёт
его оттуда и печатает. Связи у них разные: у верхнего склад и ячейка, у нижнего — ячейка
и табло. Общая у них только ячейка.

<Card kind="note">
В примере показана программа верхнего процессора — его и правят. Нижний работает своей,
и увидеть её здесь нельзя: окно программы в игре тоже открывают у одного блока за раз.

Поэтому смотреть надо кнопкой «пуск»: «шаг» двигает только показанный процессор, а нижний
в это время стоит, и надпись на табло не меняется.
</Card>

## Зачем делить работу

Запас инструкций у процессора свой — `@ipt` за такт, — и потратить его можно только на себя.
Два процессора работают **параллельно**, и это единственный способ ускорить логику:

- медленная часть (обход связей, поиск радаром) живёт в одном процессоре и кладёт итог
  в память;
- быстрая часть (рисование на дисплее, ведение юнита) живёт в другом и берёт готовое.

Второй при этом не ждёт первого: он читает то, что лежит, и если там прошлое значение —
работает с ним.

## Договариваться приходится самим

Ячейка не умеет сказать «данные свежие» или «сейчас идёт запись». Всё, что есть, — места
и значения; смысл им придаёт уговор между программами, и записан он только в голове автора.

Отсюда простое правило: **адреса стоит подписать** — комментарием в программе или на бумаге.

| Адрес | Что лежит |
| --- | --- |
| 0 | меди на складе |
| 1 | сколько ждём |
| 2 | флаг: нужен подвоз |

<Card kind="error">
**Читатель может успеть между двумя записями.** Если первый процессор кладёт три числа
подряд, второй способен прочитать их в тот момент, когда записаны только два. Данные окажутся
полусвежими, и заметить это тяжело: ошибка мигает раз в сотню кругов.

Лечится сговором: последним пишется **признак готовности**, а читатель начинает с него.

```
write 0 cell1 3
write медь cell1 0
write норма cell1 1
write 1 cell1 3
```
</Card>

## Обмен без ячейки

Ячейка нужна не всегда. Процессор и сам читается и пишется — адресом служит **имя переменной
в кавычках**:

```
read чужойСчёт processor1 "счёт"
write 0 processor1 "счёт"
```

Первая строка достаёт переменную соседа, вторая кладёт в неё значение. Ни ячейки, ни уговора
об адресах: имена переменных и есть уговор.

| Что можно | Что нельзя |
| --- | --- |
| прочитать любую переменную соседа | завести соседу новую переменную |
| записать в существующую | переписать константу — `@pi`, `@copper` и прочие |
| достать связь соседа по имени или номеру | прочитать мировой процессор обычным |

<Card kind="error">
**Чужая переменная меняется без следа в чужой программе.** Сосед присвоил её сам, а значение
стало другим; строки, которая это сделала, в его программе нет вовсе, и искать причину он
будет у себя.

Правило простое: **писать к себе, читать у других**. Пусть каждый процессор сам отвечает
за свои переменные, а соседи их только читают. Тогда «кто это сделал» всегда видно
по программе того, чья переменная.
</Card>

Ячейка при этом не лишняя: у процессора значения живут, пока его не тронули, а правка
программы их обнуляет — и сосед в ту же секунду начнёт читать нули.

## Что ещё годится общим

- **Ячейка** — 64 места, размер 1×1: хватает на уговор из нескольких чисел.
- **Банк** — 512 мест: списки, очереди, таблицы.
- **Сам процессор** — переменные соседа по именам, без лишнего блока на карте.
- **Блок сообщений** — только текст и только для человека: программа читать его не умеет.

Обратная сторона: любой процессор, подключённый к ячейке, может в неё **писать**. Защиты нет,
и случайная запись по чужому адресу выглядит как «данные портятся сами».

<Card kind="recap">
- Переменные у каждого процессора свои, но сосед может прочитать их по имени.
- Ячейка и банк видны всем, кто к ним подключён, и писать в них может каждый.
- Делить работу стоит по скорости: медленное считает один, быстрое берёт готовое.
- Ячейка не знает, что в ней лежит: смысл адресов — уговор между программами.
- Признак готовности пишут последним, а читают первым.
- В чужие переменные лучше не писать: изменение будет непонятно откуда.
</Card>

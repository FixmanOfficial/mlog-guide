`write` — это `read` наоборот. Поля стоят в том же порядке, и первое из них теперь значит
«что записать»:

```
write кругов cell1 0
```

<Example client:load scene={STORE} world={true} />

Счётчик здесь живёт не в переменной, а в памяти: круг начинается с того, что программа
достаёт прошлое значение, и кончается тем, что кладёт новое.

## Зачем так, если есть переменная

В этом примере — незачем: переменная справилась бы сама. Разница видна, когда программу
трогают.

| Что случилось | Переменная | Ячейка |
| --- | --- | --- |
| прошёл круг | помнит | помнит |
| программу отредактировали | обнулилась | помнит |
| процессор снесли и поставили заново | обнулилась | помнит |
| смотрит другой процессор | не видит | видит |

Правка программы обнуляет переменные не по злому умыслу: процессор пересобирает их заново
из текста, и старых значений взять неоткуда. Ячейка — отдельный блок, и до неё это
не дотягивается.

<Card kind="note">
Сохранение и загрузку карты содержимое памяти тоже переживает: оно лежит в файле сохранения
вместе с блоком.
</Card>

## Границы те же, что у чтения

| Адрес | Что будет |
| --- | --- |
| `2.9` | запись в место 2: дробная часть отбрасывается |
| `64` у ячейки | **ничего**: строка выполнится, память не изменится |
| `-1` | то же самое — ничего |

<Card kind="error">
Запись за границей не ругается и не падает — она просто не происходит. Если программа
считает адрес сама, ошибка в счёте будет выглядеть как «данные не сохраняются», а не как
ошибка. Проверять стоит адрес, а не результат:

```
jump 6 greaterThanEq адрес мест
write значение cell1 адрес
```
</Card>

## Одно место — одно значение

Запись затирает то, что лежало по адресу, целиком. Ни «добавить к тому, что было», ни
«записать половину места» нельзя: чтобы увеличить число в памяти, его сначала читают.

```
read счёт cell1 0
op add счёт счёт 1
write счёт cell1 0
```

Три строки вместо одной — обычная цена памяти. Поэтому счётчик, который нужен только
внутри круга, держат в переменной, а в память кладут то, что должно пережить круг.

<Card kind="recap">
- `write значение ячейка адрес` — те же поля, что у `read`, в том же порядке.
- Память переживает правку программы, снос процессора и сохранение карты.
- Дробный адрес усекается; за границей памяти запись молча не происходит.
- Запись затирает место целиком, поэтому «прибавить» — это прочитать, сложить, записать.
</Card>

<Card kind="task">
Запустите пример и дайте ему поработать. Потом, не останавливая, поправьте в программе
`wait 0.5` на `wait 0.1`: счётчик продолжит с того места, где был, а не с единицы —
он лежит не в процессоре.

Теперь поменяйте адрес у `write` с `0` на `64`, оставив у `read` ноль. Надпись замрёт
на единице: читается всегда одно и то же место, а запись уходит в никуда.
</Card>

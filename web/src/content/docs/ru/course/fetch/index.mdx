```
fetch unitCount своихЮнитов @sharded 0 0
fetch buildCount турелей @sharded 0 @duo
fetch core ядро @sharded 0 0
```

Три вопроса к карте: сколько у нас юнитов (двое), сколько двойных турелей (тоже две)
и где ядро. Расстояние тут ни при чём — `fetch` видит всю карту разом.

| Поле | Что в нём |
| --- | --- |
| первое | что достаём: `unit`, `build`, `core` или их счётчики |
| второе | куда положить |
| третье | **команда** |
| четвёртое | номер в списке, считая с нуля |
| пятое | отбор по типу: блок для `build`, тип юнита для `unit` |

## Восемь видов и два вопроса

Виды делятся пополам: половина отдаёт **сам объект** по номеру, половина — **сколько их**.

| Отдаёт объект | Отдаёт число |
| --- | --- |
| `unit` | `unitCount` |
| `build` | `buildCount` |
| `core` | `coreCount` |
| `player` | `playerCount` |

Отсюда обычный вид перебора: сначала спросить счёт, потом ходить по номерам.

```
fetch unitCount сколько @sharded 0 0
set номер 0
fetch unit юнит @sharded номер 0
sensor здоровье юнит @health
op add номер номер 1
jump 2 lessThan номер сколько
```

<Card kind="note">
Пятое поле — необязательный отбор. `fetch buildCount n @sharded 0 @duo` считает только
двойные турели, а `fetch unit u @sharded 0 @poly` ходит только по поли. Без отбора идут все.
</Card>

## Порядок и его хрупкость

Список идёт **в порядке появления**: кто раньше построен или создан, тот и раньше в списке.
Номера в нём не закреплены ни за кем: погибнет юнит с номером 3 — всё, что было после,
сдвинется на единицу.

<Card kind="error">
**Номер из `fetch` нельзя запоминать между итерациями.** К следующей итерации программы под
этим номером будет уже другой юнит — или его не будет вовсе.

Запоминать нужно **сам объект**: `fetch unit мой @sharded 3 0`, потом `set запомнил мой`.
Объект остаётся тем же, даже когда список перетасовался, а `sensor @dead` подскажет, жив ли он.
</Card>

## Чем это отличается от радара и query

| | `radar` | `query` | `fetch` |
| --- | --- | --- | --- |
| где ищет | вокруг здания | в области карты | по всей карте |
| что отдаёт | одного | всех в области | одного по номеру или счёт |
| кому доступен | всем | мировому | мировому |
| ищет здания | нет | да | да |

`fetch` — единственный способ спросить «а сколько у врага юнитов вообще» или «где у него ядро»,
не обходя карту клетками.

<Card kind="recap">
- `fetch вид куда команда номер отбор` достаёт юнитов, здания и ядра команды.
- Половина видов отдаёт объект, половина — количество.
- Пятое поле отбирает по типу блока или юнита.
- Порядок — порядок появления, и номера в нём съезжают.
- Запоминают объект, а не номер.
</Card>

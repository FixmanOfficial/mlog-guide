Переменные процессора — его личное дело: другой процессор их не видит, а при правке программы
они обнуляются. Общая и долгая память живёт на карте отдельным блоком: **ячейка памяти**
и **блок памяти**. `read` достаёт из неё значение по номеру места.

<Example client:load scene={CELLS} world={true} />

Ячейка на этой карте пришла заполненной: её содержимое лежит в сохранении, а не заводится
заново при запуске. Программа достаёт из неё три числа и печатает два из них в блок
сообщений.

## Строка читается как «переменная = откуда адрес»

| Поле | Что в нём |
| --- | --- |
| первое | куда положить прочитанное |
| второе | **откуда** читаем — здесь это ячейка или блок памяти, но бывает и другое |
| третье | **адрес**: номер места, считая с нуля |

```
read запас cell1 0
```

Мест в ячейке 64, в блоке памяти 512. Спрашивать об этом саму память умеет `sensor`:

```
sensor мест cell1 @memoryCapacity
```

<Card kind="note">
Блок памяти — та же ячейка, только больше: 512 мест вместо 64, 2×2 вместо 1×1, прочнее
и дороже. Инструкции, адреса и правила у них общие.
</Card>

## Адрес усекается, а за границей лежит пустота

<Example client:load scene={BOUNDS} world={true} />

Здесь видно оба правила сразу:

- `read дробный cell1 1.9` достаёт **место 1**, а не 2: дробная часть адреса отбрасывается,
  а не округляется. `1.9` и `1.0` — один и тот же адрес;
- `read заГраницей cell1 64` даёт `null`. Мест 64, они с нуля до 63, и шестьдесят четвёртого
  нет — но ошибки тоже нет: переменной просто присваивается пустота. Отрицательный адрес —
  то же самое;
- `read пустое cell1 7` даёт `0`: место есть, оно внутри ячейки, и в нём лежит ноль.

<Card kind="note">
**Ноль и пустота — не одно и то же.** Ноль означает «место есть, в нём ноль», пустота —
«места нет вовсе». Отличить их можно строгим сравнением (`===` в блоке, `strictEqual`
в тексте), а вот арифметикой не выйдет: `op add x пусто 1` даст `1`, потому что пустота
в арифметике считается нулём. Подробнее — в уроке <Lesson lesson="basics/null">«Пустота:
null»</Lesson>.
</Card>

## Цикл по памяти

Перебор всей памяти — обычное дело, и границу для него лучше спрашивать, а не вписывать
числом:

```
sensor мест cell1 @memoryCapacity
set адрес 0
read значение cell1 адрес
op add сумма сумма значение
op add адрес адрес 1
jump 2 lessThan адрес мест
```

С числом `64` вместо `мест` программа сломается молча в тот день, когда ячейку заменят
на блок памяти: она пройдёт первые 64 места из 512 и решит, что остальное пусто.

<Card kind="recap">
- Ячейка и блок памяти — общая память на карте: в ячейке 64 места, в блоке памяти 512.
- `read` кладёт в переменную значение по адресу, адреса считаются с нуля.
- Дробный адрес усекается, а не округляется.
- За границей памяти лежит пустота, а не ноль, и ошибкой это не считается.
- Границу цикла берут у самой памяти — `sensor @memoryCapacity`.
</Card>

<Card kind="task">
Поменяйте в первом примере адрес у `read запас` с `0` на `3` и запустите: на табло появится
`запас 0 из 300` — место есть, в нём ноль.

Потом поставьте адрес `100`. Надпись станет `запас null из 300`: за границей памяти лежит
пустота, и `print` печатает её словом `null`.

Напоследок допишите в конец `sensor мест cell1 @memoryCapacity` и посмотрите в таблицу
переменных: 64. Это то число, которым должен кончаться цикл по памяти, — и оно же станет
512, если однажды поставить блок памяти вместо ячейки.
</Card>

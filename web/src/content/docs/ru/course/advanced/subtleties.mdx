## `equal` сравнивает с допуском

`0.1 + 0.2` в mlog, как и везде, даёт `0.30000000000000004`. Но `op equal почти 0.3`
отвечает **единицей**: сравнение с допуском — два числа считаются равными, если разница
меньше одной миллионной. Строгое сравнение той же пары даёт ноль.

Тот же пример показывает и остальное: деление на ноль превратилось в пустоту, пустота
оказалась равна нулю по `equal` и не равна по `strictEqual`, а медь равна только меди.

<Example client:load scene={EDGE} world={false} />

| Условие | Как сравнивает |
| --- | --- |
| `equal`, `notEqual` | с допуском в 0.000001 |
| `strictEqual` | точно, и ещё проверяет тип |
| `lessThan`, `greaterThan` и прочие | точно, без допуска |

Отсюда странность: `equal` может сказать «равны», а `lessThan` — «меньше», и оба правы.

<Card kind="note">
Допуск — подарок, а не помеха: без него сравнивать дробные результаты было бы почти
невозможно. Помнить о нём стоит в одном случае: когда числа маленькие. `0.0000005`
и ноль для `equal` — одно и то же.
</Card>

## Деление на ноль даёт пустоту

Ни бесконечности, ни «не числа» в переменных mlog не бывает. Стоит вычислению дать такой
ответ — и переменная становится **пустой**:

```
op div x 5 0        // x = null
op div y 0 0        // y = null
op sqrt z -4        // z = null
```

Это не наша выдумка, а устройство переменной в игре: негодное число она не хранит вовсе
и превращается в пустоту.

<Card kind="error">
**Отсюда молчаливая порча данных.** Программа поделила на ноль, положила «результат»
в ячейку памяти, и там оказалась пустота. Дальше арифметика считает её нулём, `print`
печатает `null`, а искать причину придётся в двадцати строках выше.

Проверять стоит делитель, а не результат: `jump ... equal делитель 0` до деления.
</Card>

## Пустота в сравнениях

| Сравнение | Ответ |
| --- | --- |
| `equal null 0` | **1** — в арифметике пустота считается нулём |
| `strictEqual null 0` | 0 — тип разный |
| `op add x null 5` | `5` |
| `print null` | `null` |

Пустота — не ноль, но ведёт себя как ноль везде, кроме строгого сравнения и печати.
Единственный надёжный способ отличить «нет значения» от «значение ноль» — `strictEqual`.

## Объекты равны только сами себе

Здания, юниты и контент сравниваются **по тождеству**: `equal @copper @copper` — единица,
`equal @copper @lead` — ноль. Никакого «похожи» нет.

С этим связаны две вещи:

- **два юнита одного типа не равны.** Чтобы сравнить типы, спрашивают `sensor тип @unit @type`
  и сравнивают уже типы;
- **здание из `getlink` и то же здание из `radar` — один и тот же объект**, и сравнение
  их подтвердит.

<Card kind="note">
Сравнение объекта с числом всегда даёт ложь, кроме одного случая: объект в числовом
сравнении считается единицей, если он есть, и нулём, если это пустота. Поэтому
`jump ... equal @unit 0` работает как проверка «юнита нет» — хотя писать так не стоит:
`equal @unit null` понятнее.
</Card>

## Строка — это значение, но не число

Строку можно положить в переменную, напечатать, сравнить на равенство и прочитать
посимвольно через <Lesson lesson="read/strings">`read`</Lesson>. Чего с ней нельзя —
складывать и сравнивать по порядку:

```
op add x "abc" 5        // не сложение: строка в арифметике — единица
op lessThan y "abc" 5   // сравнивает не строку, а единицу
```

В числовых операциях строка ведёт себя как объект: есть — единица, нет — ноль.

<Card kind="recap">
- `equal` сравнивает с допуском в одну миллионную, `strictEqual` — точно и по типу.
- Деление на ноль и корень из отрицательного дают **пустоту**, а не бесконечность.
- Пустота равна нулю в арифметике и в `equal`, но не в `strictEqual`.
- Объекты равны только сами себе; типы сравнивают через `sensor @type`.
- Строка в арифметике считается единицей.
</Card>

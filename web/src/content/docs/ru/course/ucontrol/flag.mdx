Перебор выдаёт юнитов по кругу, и программа каждый раз получает кого-то нового. Чтобы
не путать их между собой, юнита **помечают**:

```
ucontrol flag 7 0 0 0 0
```

Теперь у него в `@flag` лежит семёрка. Прочитать её может любой процессор:

```
sensor метка @unit @flag
```

<Example client:load scene={FLAG} world={true} />

Программа раздаёт номера: у кого метки нет (ноль) — тому выдаётся следующая, у кого есть —
тот пропускается. Три поли получают единицу, двойку и тройку, и `последний` останавливается
на трёх: помечать больше некого.

## Зачем это нужно

Флаг — **единственная память, которая живёт на самом юните**, а не в процессоре и не
в ячейке. Отсюда и все его применения:

- **разделить отряд.** Метка `1` возит медь, метка `2` копает, метка `3` чинит. Каждый
  процессор смотрит на флаг и пропускает чужих;
- **не хватать одного и того же дважды.** Пометив юнита, программа видит, что он уже
  занят — даже если забыла его между итерациями;
- **передать юнита другому процессору.** Один помечает, другой читает: общаться через флаг
  дешевле, чем через ячейку памяти, и метка всегда при юните;
- **посчитать своих.** Перебор плюс проверка флага — и ясно, сколько юнитов уже разобрано
  по делам.

```
ubind @poly
sensor метка @unit @flag
jump 0 notEqual метка 1
ucontrol move 20 30 0 0 0
```

Такой процессор командует только «первыми» — остальных он молча пролистывает.

<Card kind="note">
Флаг — обычное число со всеми его свойствами, и в него влезает многое: например, номер
задачи и координата, упакованные вместе. Правда, «многое» упирается в то, сколько
<Lesson lesson="advanced/numbers">целых чисел помещается в число</Lesson> — 53 бита,
и на этом всё.
</Card>

## Чего флаг не умеет

<Card kind="error">
**Флаг не переживает гибель юнита.** Новый юнит того же типа приходит с нулём, и все метки
надо раздавать заново. Программа, которая раздаёт метки один раз на старте, после первой
же потери юнита останется с дырой в отряде.

Поэтому раздачу держат в цикле — как в примере: ноль означает «не размечен», и новичок
получает номер сам собой.
</Card>

Флаг не видит враг — как и всё остальное у чужих юнитов. Флаг не показывается в игре:
ни цифры над юнитом, ни подсветки. И флага нет у зданий: там роль метки играет
<Lesson lesson="write/cells">ячейка памяти</Lesson> или настройка блока.

<Card kind="recap">
- `ucontrol flag число` кладёт метку на юнита, `sensor @flag` её читает.
- Флаг живёт на юните и виден всем своим процессорам.
- Им делят отряд на роли и отмечают уже занятых.
- Ноль означает «не размечен» — с него начинают все юниты.
- Гибель стирает метку: раздачу держат в цикле.
</Card>

<Card kind="task">
Поменяйте в примере `jump 6 notEqual метка 0` на `jump 6 notEqual метка 99`: программа
решит, что размечать надо всех и каждую итерацию, и `последний` полетит вверх без остановки.

Потом верните как было и допишите после `ucontrol flag` строку `ucontrol move 3 3 0 0 0`:
размеченные юниты соберутся в одном углу — метка и команда обычно ходят вместе.
</Card>

```
setrule unitMineSpeed 4 0 0 0 0
```

Одна строка — и юниты копают вчетверо быстрее. Моно на этой карте набивает свои двадцать меди
за пять секунд вместо двадцати.

| Поле | Что в нём |
| --- | --- |
| первое | какое правило |
| второе | значение |
| остальные четыре | углы области — только для правила `mapArea` |

Правило меняется **сразу и для всей игры**, а не для одного юнита или здания. Вернуть
его назад можно тем же `setrule` с прежним значением: сама собой настройка не откатится.

## Что можно менять

| Правило | Что делает |
| --- | --- |
| `unitHealth`, `unitDamage` | множители живучести и урона юнитов |
| `unitMineSpeed`, `unitBuildSpeed` | как быстро юниты копают и строят |
| `unitCap`, `unitCost` | сколько юнитов можно и во сколько они обходятся |
| `blockHealth`, `blockDamage` | то же для зданий |
| `buildSpeed` | скорость стройки игроком |
| `waves`, `waveSpacing`, `waveTimer` | идут ли волны, как часто, тикает ли таймер |
| `wave`, `currentWaveTime`, `waveSending` | номер волны, время до неё, отправить сейчас |
| `attackMode`, `canGameOver` | режим атаки и можно ли проиграть |
| `enemyCoreBuildRadius`, `dropZoneRadius` | запретные зоны вокруг ядра и точки высадки |
| `lighting`, `ambientLight`, `unitLight` | темнота на карте и свет |
| `mapArea` | играемая часть карты: четыре угла |
| `ban`, `unban` | запретить или разрешить блок или юнита |
| `pauseDisabled`, `musicVolume`, `solarMultiplier`, `dragMultiplier` | по мелочи |

<Card kind="note">
**Секунды и клетки переводятся сами.** `waveSpacing 30` — это тридцать секунд, а не тридцать
тиков; `dropZoneRadius 5` — пять клеток. Инструкция переводит их во внутренние единицы игры,
и писать тики или мировые единицы не нужно.
</Card>

## Множитель живучести не поднимает здоровье

<Example client:load scene={TOUGH} world={true} />

Здесь вспышка стоит под огнём вражеской турели, а правило `unitHealth 4` включено. Смотрите
на `предел`: он так и остался **70**. А вот здоровье падает вчетверо медленнее, и вспышка
переживает обстрел, который раньше её убивал.

<Card kind="error">
**`unitHealth` и `blockHealth` делят урон, а не умножают здоровье.** В `@health`
и `@maxHealth` эти правила не видны вовсе — программа, которая ждёт роста чисел, ничего
не дождётся.

Проверять такие правила приходится по последствиям: сколько ударов держит юнит, а не что
показывает `sensor`.
</Card>

## Запрет и границы

Два правила стоят особняком, потому что берут не число:

```
setrule ban @duo 0 0 0 0
setrule mapArea 0 2 2 10 5
```

`ban` и `unban` принимают **контент**: блок или юнита. Запрещённый блок пропадает из меню
строительства, а запрещённый юнит перестаёт производиться.

`mapArea` — единственное правило, которому нужны все четыре последних поля: левый край,
нижний край, ширина и высота играемой области. Так в кампании открывают карту по кусочкам.

<Card kind="recap">
- `setrule правило значение` меняет настройку всей игры на ходу.
- Секунды и клетки переводятся сами.
- `unitHealth` и `blockHealth` делят урон, а не поднимают здоровье.
- `ban` и `unban` берут контент, `mapArea` — четыре числа области.
- Обратно правило само не вернётся: возвращают его тем же `setrule`.
</Card>

<Card kind="task">
В первом примере поменяйте `4` на `0.25`: добыча станет вчетверо медленнее обычной,
и за то же время моно наберёт всего пару единиц.

Во втором примере поставьте `unitHealth 1`: вспышка снова погибнет — правило вернулось
к обычному.
</Card>

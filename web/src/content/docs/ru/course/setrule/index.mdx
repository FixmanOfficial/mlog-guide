```
setrule unitMineSpeed 4 @sharded 0 0 0
```

Одна строка — и юниты команды копают вчетверо быстрее. Моно на этой карте набивает свои
двадцать меди чуть больше чем за две секунды вместо девяти.

| Поле | Что в нём |
| --- | --- |
| первое | какое правило |
| второе | значение |
| третье | **команда** — у десяти правил-множителей |
| остальные | углы области — только для правила `mapArea` |

Правило меняется сразу и целиком: не для одного юнита и не для одного здания, а для всех
разом. Вернуть его назад можно тем же `setrule` с прежним значением — сама собой настройка
не откатится.

<Card kind="error">
**У множителей третье поле — команда, а не пустое место.** `unitHealth`, `unitMineSpeed`,
`blockHealth` и ещё семь правил живут не у мира, а **у команды**: `setrule` берёт её
из третьего поля и, если там не команда, молча не делает ничего.

```
setrule unitMineSpeed 4 0 0 0 0
```

Такая строка не сломается и не пожалуется — просто ускорит добычу **заброшенным**: ноль
это команда с номером ноль. Своим нужен `@sharded`, врагу `@crux`. В редакторе игры это
поле так и подписано — «of», и стоит там по умолчанию `@sharded`.
</Card>

## Что можно менять

Правил три десятка, и делятся они на четыре вида по тому, что берут во втором поле:

| Вид | Примеры |
| --- | --- |
| число | `unitCap`, `waveSpacing`, `musicVolume` |
| «да/нет» | `waves`, `attackMode`, `canGameOver`, `lighting` |
| множитель команды | `unitHealth`, `unitMineSpeed`, `blockHealth`, `buildSpeed` |
| особые | `ban` и `unban` берут контент, `mapArea` — четыре числа |

Полный список — в справочнике: [«Правила игры»](/ru/reference/rules/). Там же видно, какое
правило требует команду, какое считает в секундах, а какое в клетках, и в каких границах
игра зажимает значение.

<Card kind="note">
**Секунды и клетки переводятся сами.** `waveSpacing 30` — это тридцать секунд, а не тридцать
тиков; `dropZoneRadius 5` — пять клеток. Инструкция переводит их во внутренние единицы игры,
и писать тики или мировые единицы не нужно.
</Card>

## Множитель живучести не поднимает здоровье

<Example scene={TOUGH} world={true} />

Здесь вспышка стоит под огнём вражеской турели, а правило `unitHealth 4` включено. Смотрите
на `предел`: он так и остался **70**. А вот здоровье падает вчетверо медленнее, и вспышка
переживает обстрел, который раньше её убивал.

<Card kind="error">
**`unitHealth` и `blockHealth` делят урон, а не умножают здоровье.** В `@health`
и `@maxHealth` эти правила не видны вовсе — программа, которая ждёт роста чисел, ничего
не дождётся.

Проверять такие правила приходится по последствиям: сколько ударов держит юнит, а не что
показывает `sensor`.
</Card>

## Запрет и границы

Два правила стоят особняком, потому что берут не число:

```
setrule ban @duo 0 0 0 0
setrule mapArea 0 2 2 10 5
```

`ban` и `unban` принимают **контент**: блок или юнита. Запрещённый блок пропадает из меню
строительства, а запрещённый юнит перестаёт производиться.

`mapArea` — единственное правило, которому нужны все четыре последних поля: координаты
левого нижнего угла, а за ними ширина и высота играемой области. Так в кампании открывают
карту по кусочкам.

<Card kind="recap">
- `setrule правило значение` меняет настройку всей игры на ходу.
- У десяти правил-множителей третье поле — команда, и без неё строка молчит.
- Секунды и клетки переводятся сами.
- `unitHealth` и `blockHealth` делят урон, а не поднимают здоровье.
- `ban` и `unban` берут контент, `mapArea` — четыре числа области.
- Обратно правило само не вернётся: возвращают его тем же `setrule`.
</Card>

<Card kind="task">
В первом примере поменяйте `4` на `0.25`: добыча станет вчетверо медленнее обычной,
и за первые десять секунд моно наберёт пять штук вместо двадцати. На полный трюм ему
понадобится больше половины минуты.

Во втором примере поставьте `unitHealth 1`: вспышка снова погибнет — правило вернулось
к обычному. А если вместо этого стереть `@sharded` и написать `0`, случится то же самое:
множитель уйдёт заброшенным, а вспышка останется без защиты.
</Card>
